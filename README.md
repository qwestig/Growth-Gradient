# Growth Gradient: прогноз РТО на март 2025

## Текущий лучший результат

Лучший public score: `89.65`.

Финальный CSV:

`submissions/test_best_gru_momentum_bias_8965.csv`

Решение состоит из двух уровней:

1. Базовый прогноз: сезонная эвристика для марта 2025.
2. Улучшение: GRU-модель residual correction плюс сегментная momentum-bias correction.

## Что именно дало прирост

Изначально лучший стабильный файл был:

`submissions/test_gru_alpha070.csv`

Он дал public score `89.52`. Эта модель не работала с полностью сырым РТО. Внутри GRU использовались нормализованные временные признаки:

- `rel_log_rto = log(history) - log(last_value)`;
- `log_growth = log(y_t) - log(y_{t-1})`;
- календарные признаки месяца;
- лаговые поведенческие признаки магазина;
- статические признаки магазина через numeric scaling и categorical embeddings.

После этого была найдена системная ошибка GRU: качество зависело от `momentum_raw`.

```text
momentum_raw = РТО февраля / средняя РТО за декабрь, январь и февраль
```

Логика оказалась такой:

- если февраль слабый относительно последних трех месяцев, GRU слегка недооценивает март;
- если февраль слишком сильный, GRU слегка переоценивает март;
- значит нужна не глобальная калибровка, а сегментная поправка по momentum.

Лучшая public-версия:

```text
segment = momentum_raw_bin
shrink_k = 500
beta = 1.00
clip = 0.02
```

Public score улучшился:

```text
GRU alpha=0.70                    89.52
momentum correction k500 beta .75 89.63
momentum correction k500 beta 1.0 89.65
```

## Почему это не просто подгонка масштаба

Глобальная калибровка прогноза вокруг лучшего GRU провалилась: один из масштабированных вариантов дал около `89.28`.

Это важный вывод: ошибка была не в том, что все прогнозы нужно поднять или опустить. Ошибка была сегментной. Разные магазины нужно двигать в разные стороны в зависимости от режима февральской динамики.

## Что проверяли и что не сработало

### CatBoost residual

CatBoost с большим набором лаговых, сезонных, групповых и статических признаков локально выглядел неплохо, но public score не превзошел GRU.

Бленд GRU + CatBoost тоже не перенесся: один из лучших локальных блендов дал public score `89.49`, хуже standalone GRU.

Вывод: CatBoost-сигнал не был достаточно устойчивым поверх GRU.

### Random Forest

Random Forest проверялся как простой ML-бейзлайн. Он не дал преимущества над линейной/эвристической и GRU-веткой.

Вывод: обычное табличное дерево без аккуратной временной структуры не решает главную ошибку.

### Transformer

Transformer residual был проверен как альтернатива GRU. Public score оказался ниже GRU.

Вывод: усложнение архитектуры само по себе не помогает, если не меняется полезное представление временного ряда.

### GRU seed ensemble

Ансамбль нескольких GRU seed локально выглядел приемлемо, но public score просел.

Вывод: public не вознаградил усреднение похожих GRU-моделей.

### Multi-month GRU

Пробовали обучать residual-модель не только на март-2024, а на нескольких целевых месяцах. Локально эта идея была слабее март-специфичной GRU.

Вывод: мартовый переход февраль-март имеет собственную структуру, и ее лучше моделировать отдельно.

### DLinear из экспертного TS/DL notebook

По мотивам экспертного `TS_DL.ipynb` был реализован DLinear residual experiment с разложением ряда на trend и residual.

Лучший локальный DLinear:

```text
kernel = 7
alpha = 0.70
MAPE = 3.4779
```

Текущий GRU локально:

```text
MAPE = 3.4417
```

Вывод: экспертная идея полезна как проверка, но наш GRU уже использовал похожие нормализации ряда и оказался сильнее.

### Глобальное масштабирование

Масштабирование лучшего GRU вверх/вниз не сработало.

Вывод: проблема не глобальная, а сегментная.

## Итоговая интерпретация

На текущем этапе лучший результат дала не новая сложная архитектура, а правильная диагностика ошибки:

1. GRU хорошо ловит общую временную динамику.
2. Остаточная ошибка зависит от режима февральского momentum.
3. Сегментная multiplicative correction по `momentum_raw_bin` устойчиво улучшила public score.

Именно поэтому финальный файл называется:

`test_best_gru_momentum_bias_8965.csv`
